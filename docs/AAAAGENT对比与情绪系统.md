# AAAAGENT 对比与本项目的情绪系统

研究日期：2026-09-23。参考：**AAAAGENT — phoiex 及项目贡献者**，提交 [`2752349bcc7f7137b8b9e4ff9cccf34026d77aad`](https://github.com/phoiex/AAAAGENT)。

## 对比结论

本项目适合继续以 Windows 桌宠、本地模型和可管理记忆为核心。AAAAGENT 值得参考的是情绪来源追踪、角色表现与对话的协调，以及把工作任务与陪伴记忆分开的设计。

| 方面 | AAAAGENT 当前做法 | 我们的做法与判断 |
|---|---|---|
| 桌面架构 | macOS 主版本与独立 Windows Electron 目录 | Python/Qt 桌宠通过 HTTP 连接服务；统一根目录启动 exe，保留现有架构可以复用本地推理与语音工具 |
| 模型与语音 | 文本、ASR、图像、TTS 分别有供应商适配层 | llama.cpp 本地 GGUF 或兼容 API；Whisper、神经语音及本地音色工具。继续完善本地可用性与切换状态 |
| 记忆召回 | 当前以关键词及短语匹配为主，并对最近完整轮次安排独立预算 | 已有向量/词法混合召回、档案、实体关系与重排；保留这套能力，下一步改进最近完整问答的预算优先级 |
| 情绪 | 分离本轮观察、用户持续情绪与角色心情，消息冻结快照，来源失效后不再使用相关判断 | 本次新增独立情绪服务、来源校验、快照、网页查询和表现联动；不把短暂情绪写成永久用户性格 |
| 角色表现 | Live2D 参数与动作需要按实际模型适配 | 当前三套 PNG 立绘、程序动画和可选 Live2D 导入；先把鼠标区域和实际画面对应，再接入专属骨骼与表情 |
| 工作任务 | 任务卡经确认后交给外部工作 Agent | 当前集中在陪伴；建议保持任务执行记录与陪伴记忆分开，等桌宠交互稳定后再做 |

## 本次实现

- 35%–300% 缩放；每格滚轮细调 2%，高精度触控板的小增量同样生效，约 16ms 一帧渐变。缩放尽量保持鼠标指向的位置，停止滚动后再保存，避免每帧写文件。
- 仅保留“更换形象”，同时切换角色人格、初始介绍和声音。
- 鼠标点头部、脸颊、身体分别触发摸头、戳脸和轻拍；点嘴巴投喂；长按拥抱、双击聊天、拖动移动。PNG 使用绘制变换的逆变换做命中测试，透明区域不触发触摸。
- 情绪入口：网页 **记忆 → 情绪**；桌宠名字旁展示自己的心情，摆动、呼吸幅度与声音参数随心情调整。

### 情绪怎样产生

`src/core/emotion.py` 负责分析与持久化，`src/core/chat.py` 在每轮对话接入。

1. 保存本轮用户消息，并冻结当时已有情绪背景。
2. 简短明确的第一人称当下表述先走本地规则。例如“我很难过”识别为难过，“我不难过了”清除先前标签；第三人称、引文与复杂否定交给上下文分析。
3. 其他输入使用**当前配置的同一个聊天模型**，读取最近最多 6 条消息及当前输入，分别产生用户情绪与角色心情。没有新增独立云端供应商。此阶段有默认 4 秒上限，超时、坏 JSON 或非法分值不阻断正常聊天。
4. 强度与置信度未提供时保留 `null`，页面显示“未估计”。低置信度观察保留供查看，不覆盖持续状态。有效状态默认 6 小时后不再参与回应。
5. 用户情绪可以是难过；桌宠心情可以是关心。标签进入对话提示前检查剩余预算，不挤掉已有对话和记忆。
6. 回复保存时另存一份快照；后续分析不会回写旧快照。声线身份保持不变，语速、音高与支持的情感参数轻微调整。

和上游的一个实现差异：上游从既有对话结果读取结构化情绪字段；我们现有聊天协议是纯文本流，本次采用独立、限时的分类请求，避免 JSON 混进聊天或朗读。这会给非明确情绪输入增加一次模型调用。后续应合并成同一次生成的独立元数据段，并对分块截断、解析失败做验证。

### 数据边界

情绪观察绑定角色、会话和消息 ID，来源保存内容指纹。来源消息被删除或修改后，相应判断失效；迟到结果按原消息发生顺序处理，不按返回顺序覆盖更新的状态。角色间隔离。情绪分析仅看近期文本，不读取长期记忆中的第三方经历。

历史清理工具：停止服务后运行 `python tools/clear_history.py --apply`，同时清空主数据库、既有历史数据库备份、全文索引、向量、档案、实体关系、摘要、提取队列状态和情绪记录；进行数据库压缩并截断相关运行日志。本次删除按用户要求执行，不新建个人数据备份。角色的初始介绍、模型、音色与配置保留。

当前没有声学情绪分类、摄像头情绪识别或经过验证的心理状态测量；文字判断仍可能误解反讽和混合情绪。尚未提供逐条情绪人工编辑入口，可通过正常对话说明当前感受。

### 验证记录

原有完整测试 195 项通过；修复离线换角色、透明区域双击和记忆模块不可用时的回复持久化后，相关回归 74 项通过。无界面浏览器检查通过，打包程序完成运行库导入、三套角色渲染和后端连接自检。

使用本机 `Qwen3.5-9B-Q4_K_M`，在临时数据库中验证失落表达、第三人称、开心表达和撤回情绪判断。前三条分类耗时约 0.18～0.61 秒；第三人称没有被标为用户难过。纠正用例最初被推测为平静，收紧分类提示后返回 `unknown`。这些是有限冒烟样例，不是情绪识别准确率评测；测试对话没有写入用户数据库。

停止服务后清空主库及 6 份历史备份，均通过 SQLite 完整性检查。重新启动根目录 exe 后，角色列表仅有樱樱、薄荷、露娜；会话、记忆、档案、向量和情绪记录均为零。桌宠正常显示，启动没有新增浏览器进程。本机目前使用哈希嵌入降级方案，8082 重排服务未启动；混合召回架构已具备，但完整语义召回效果仍需部署相应支持模型后验证。

## 后续开发建议

| 顺序 | 建议 | 可验收结果 |
|---|---|---|
| 1 | 将情绪元数据并入一次模型生成，统一文字、语音与表情事件 | 测量首字延迟、语音首包延迟；标签不进入朗读；取消后不再播放旧回复 |
| 2 | 给三位角色制作或导入匹配的完整 Live2D 模型，分别定义表情与点击区域 | 关心、开心、好奇有明确不同表现；不同缩放下点击命中同一部位；麦克风和拖动不误触 |
| 3 | 建立情绪回归语料，增加“不是这个意思”的纠正入口 | 覆盖否定、第三人称、引文、反讽和混合情绪；能查看误判并使其后续影响失效 |
| 4 | 补齐嵌入和重排支持模型，改进最近完整轮次预算，以及记忆纠正/遗忘时的异步处理边界 | 验证语义召回相对哈希方案的提升；小上下文不会留下孤立的助手回复；清空、删除及角色切换后不能恢复旧上下文 |
| 5 | 最后接入主动陪伴和工作任务卡 | 可调频率、安静时段、可取消；工作执行记录单独存放，用户确认后才外发任务 |
