# 训练自己的音色（GPT-SoVITS）

目标：拿你自己的录音，微调出一个**本地、离线、像你**的 TTS 音色，接进人设里说话。

> **最短路径**（环境已经装好时，三行命令）：
> ```powershell
> conda activate chatbot
> python tools\tts_dataset.py --input D:\voice\raw --out D:\voice\dataset --speaker my_voice
> powershell -ExecutionPolicy Bypass -File scripts\train-tts.ps1 -DataDir D:\voice\dataset -Speaker my_voice
> ```
> 下面把每一步的输入输出、验收标准、坑都写清楚了。第 0 节先用 30 秒确认环境没问题。

## 一、先说清楚：三条路线怎么选

| 方案 | 需要训练吗 | 数据量 | 相似度上限 | 显存/速度 | 适合 |
|---|---|---|---|---|---|
| **IndexTTS2**（零样本克隆） | 不用 | 5~15 秒参考音频 | 取决于那一段 | 常驻 2~4GB，每块 1~3 秒 | 想马上换音色、随手克隆 |
| **GPT-SoVITS 微调**（本文） | 要 | 10~60 分钟干净人声 | **明显更高、更稳** | 训练 6~9GB；推理另起服务，RTF≈0.03 | 想要"就是这个人的声音" |
| 在线 edge 音色 | 不用 | 无 | 固定音色库 | 不占显存 | 只要好听、不介意联网 |

**建议**：先用 IndexTTS2 or edge 顶着用，同时按本文微调一版；微调完把 `voice.backend` 改成 `gpt_sovits` 即可，人设其它字段都不用动。

> 官方 README 明确写了：**v3/v4 需要较高质量的训练音频**，而 v1/v2/v2Pro 对普通素材更宽容。所以本项目的默认微调版本是 **v2ProPlus**（质量与 v4 相当，显存和速度按 v2 走）。

## 二、准备素材（决定成败的一步）

| 要求 | 说明 |
|---|---|
| 时长 | **10~60 分钟**。1 分钟能出声；10 分钟开始像；30 分钟以上明显稳 |
| 人数 | 只能有**一个人**说话，不能有第二个人插话 |
| 内容 | 自然连续说话。避免唱歌、耳语、喊叫、播音腔朗读混在一起 |
| 环境 | 无背景音乐、无混响、无键盘/风扇等持续噪声。**宁可短一点，也要干净** |
| 格式 | wav / mp3 / m4a / flac / mp4 都行（本项目会自动解码并重采样到 32kHz） |
| 情绪 | 录成你希望它说话的情绪；平淡素材只会训出平淡音色 |

素材放一个目录里，例如 `D:\voice\raw\`。

## 三、四步跑完

### 1. 安装（一次性，约 12GB 下载）

全部装进同一个 conda 环境 `chatbot`（默认就是它）：

```powershell
conda activate chatbot

# torch（CUDA 版）
python -m pip install torch==2.8.* torchaudio==2.8.* --index-url https://download.pytorch.org/whl/cu128

# GPT-SoVITS 自己的依赖（注意：这份清单要求 numpy<2.0，与 IndexTTS2 的 numpy==2.2.6 冲突）
python -m pip install -r D:\Harness\ChatBot\vendor\GPT-SoVITS\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python -m pip install -r D:\Harness\ChatBot\vendor\GPT-SoVITS\extra-req.txt --no-deps -i https://pypi.tuna.tsinghua.edu.cn/simple
python -m pip install pyopenjtalk opencc-python-reimplemented -i https://pypi.tuna.tsinghua.edu.cn/simple

# 把 numpy 抬回 IndexTTS2 要求的版本，然后验证两个栈都能用
python -m pip install "numpy==2.2.6" -i https://pypi.tuna.tsinghua.edu.cn/simple
python tools\check_tts_stack.py
```

仓库、预训练权重（`lj1995/GPT-SoVITS`，含 v2ProPlus）、中文 G2PW 模型、ffmpeg 都已在
`vendor\GPT-SoVITS`，不需要再下。

国内网络拉不动 GitHub 时加 `-Proxy http://127.0.0.1:7890`。

### 2. 整理数据集

```powershell
python tools\tts_dataset.py --input D:\voice\raw --out D:\voice\dataset --speaker my_voice
```

**实测的一次真实运行**（拿 7 段参考音色拼成 96 秒"录音"试流程）：

```
  共 1 个音频文件 -> D:\voice\dataset
  说话人 demo_voice / 语言 zh / 切片 3.0~10.0s
  转写模型 large-v3-turbo（cuda）
  已挂载 2 个 CUDA 运行库目录

  切片 10 条，合计 1.6 分钟
    [!] 1 条转写文本重复同一句话，手动检查一下

  dataset.list -> ...\dataset.list
  报告         -> ...\report.md
  切片目录     -> ...\sliced
```

产出的 `dataset.list` 就是 GPT-SoVITS 要的格式（`路径|说话人|语言|文本`）：

```
...\sliced\demo_recording_000.wav|demo_voice|zh|你好呀,我是你的语音伙伴。今天过得怎么样呢?
...\sliced\demo_recording_001.wav|demo_voice|zh|就先歇一会儿,慢慢来也没关系。……
```

它做四件事，并把**每一步的结果都写进报告**：

1. 解码 → 单声道 → 重采样 32kHz；
2. 裁剪首尾静音；
3. 在**静音处**切成 3~10 秒的片段（硬切会把字切一半，模型会学错发音）；
4. 峰值归一化 + Whisper 转写（也可以 `--text-file 标注.tsv` 用自己的标注，或 `--no-asr` 先只切）。

产出：

```
D:\voice\dataset\
├─ sliced\          切好的 wav
├─ dataset.list     GPT-SoVITS 格式：路径|说话人|语言|文本
├─ report.md        人看的报告（时长分布、被丢弃的片段、提醒）
└─ report.json      机器读的同一份
```

**先看 `report.md` 再训练**：如果它提示"平均切片超过 12 秒""N 条转写重复""几乎无声"，先把素材修好，比训练完再重来省时间。

> **两个已经踩过的坑（都已修好，列在这里以便你判断现象）**
> * 转写整列空白 + 报 `name 'os' is not defined`：工具少了一个 import，已修。
> * 报 `Library cublas64_12.dll is not found or cannot be loaded`：CT2 的 CUDA 后端要
>   `cublas64_12.dll`，而本机驱动是 CUDA 13，这些 DLL 只在另一个 conda 环境的 `torch\lib`。
>   工具现在会自动把它们挂进搜索路径；万一还是失败，会**自动退回 CPU int8** 继续标注
>   （慢一些，但不会让你卡在这一步）。

### 3. 训练

```powershell
# 先干跑一遍，确认路径、参数、显存与时间预估
powershell -ExecutionPolicy Bypass -File scripts\train-tts.ps1 -DataDir D:\voice\dataset -Speaker my_voice -DryRun

# 真训练（s2 声学模型 → s1 GPT 模型）
powershell -ExecutionPolicy Bypass -File scripts\train-tts.ps1 -DataDir D:\voice\dataset -Speaker my_voice
```

`-DryRun` 的实测输出（你可以拿它对照自己的情况）：

```
============================================================
 GPT-SoVITS 微调：demo_voice（v2ProPlus）
============================================================
    [OK] 数据集 10 条切片：D:\voice\dataset

==> 训练计划
  环境      : D:\conda-envs\chatbot\python.exe
  数据集    : D:\voice\dataset（10 条）
  版本      : v2ProPlus
  SoVITS(s2): epochs=8 batch=6  -> ...\gptsovits\s2_v2ProPlus.json
  GPT(s1)   : epochs=15 batch=6 -> ...\gptsovits\s1_v2ProPlus.yaml
  输出      : ...\logs
  显存预估  : s2 约 6~9GB / s1 约 5~8GB（16GB 卡足够；与对话模型同时跑会紧张）
  时间预估  : 10 分钟素材 ≈ 20~60 分钟（取决于 batch 与显卡；以实际日志为准）
  预处理    : 3 个脚本将被调用（文本/HuBERT/语义特征）

  -DryRun：以上只是计划，没有执行任何训练。
  去掉 -DryRun 即开始训练。
```

去掉 `-DryRun` 后，它会按顺序执行：

```
1-get-text.py        → 生成 2-name2text.txt（文本 → 音素）
2-get-hubert-wav32k.py → 生成 HuBERT 特征
3-get-semantic.py    → 生成语义 token
s2_train.py          → 训练 SoVITS 声学模型
s1_train.py          → 训练 GPT 模型
```

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Version` | `v2ProPlus` | `v2ProPlus` / `v2Pro` / `v2` / `v4` |
| `-SoVitsEpochs` / `-SoVitsBatch` | 8 / 6 | 显存不够就降 batch（4、3、2） |
| `-GptEpochs` / `-GptBatch` | 15 / 6 | GPT 部分 |
| `-SkipS2` / `-SkipS1` | 关 | 接着上次接着训时用 |
| `-Serve` | 关 | 只启动推理服务（见下一步） |

日志：`logs\tts-train.log`（训练脚本原始输出）。产物会复制到 `models\tts\<说话人>\`。

**时间与显存是估计值**：10 分钟素材大致 20~60 分钟训练，取决于 batch / 显卡 / 磁盘。
和对话模型同时跑会紧张（s2 训练约占 6~9GB），建议训练前 `scripts\stop.ps1` 停掉模型服务。

### 4. 接进人设

```powershell
# 启动推理服务（默认 127.0.0.1:9090）
powershell -ExecutionPolicy Bypass -File scripts\train-tts.ps1 -Serve
```

然后改 `config/personas.yaml`：

```yaml
  my_voice:
    name: 我的音色
    voice:
      backend: gpt_sovits          # 指定用微调后的模型
      reference_audio: models/voices/my_voice_ref.wav   # 推理仍需要一段参考音频
      reference_text: "这段参考音频里说的那句话"          # 填上，韵律明显更稳
      emotion: neutral
```

> 微调后的模型**仍然需要参考音频**（GPT-SoVITS 的推理方式就是"音色特征 + 参考"），
> 它决定的是推理时的音高/韵律细节，不是音色本身。

想让它变成**默认音色**：`config/config.yaml` 里把 `speech.tts_preference` 的第一位换成 `gpt_sovits`：

```yaml
speech:
  tts_preference: [gpt_sovits, indextts, edge, sapi]
```

## 四、排错

| 现象 | 原因与处理 |
|---|---|
| 训练脚本说"找不到 GPT-SoVITS 仓库" | 先跑 `scripts\install-gptsovits.ps1` |
| 说"缺少预训练权重" | 权重没下齐：重跑安装脚本（会断点续传）；用 `python tools\check_gptsovits.py --repo vendor\GPT-SoVITS` 逐项确认 |
| 切片很少 / 全被丢弃 | 素材要么太短（<3 秒），要么几乎无声；看 `report.md` 的原因 |
| `dataset.list` 里文本是空的 | 转写失败。现在工具会自己找本地 Whisper 模型、自动挂 CUDA 运行库、失败退 CPU；若仍失败就用 `--text-file 标注.tsv` 自己标（格式：`文件名<TAB>文本`） |
| 训练报缺 `2-name2text.txt` | 预处理没跑成功。可以先用 GPT-SoVITS 自带 WebUI 跑一次「1A 训练集格式化」，确认它的路径约定 |
| 显存不足（CUDA out of memory） | 降 `-SoVitsBatch` / `-GptBatch` 到 4 或 2；先 `scripts\stop.ps1` 释放对话模型 |
| 训练完声音不像 | 数据问题排在第一位：素材是否只有一个人、有没有背景音乐、情绪是否一致；其次才是 epoch |
| 推理服务连不上 | `/api/health?deep=true` 里看 `tts.backends.gpt_sovits`；确认 9090 在监听 |
| 合成报"缺少参考音频" | 人设里必须同时给 `reference_audio` 和 `reference_text` |

## 五、它和本项目其它部分怎么衔接

- **数据准备**复用了本项目的音频工具与 Whisper 安装（`speech/audio.py`、`faster-whisper`），
  所以不用另外装一套 ASR；
- **推理**是通过 HTTP 接进来的（`src/plugs/gpt_sovits_tts.py`），跑在独立环境，
  不会把 torch/numpy 的版本冲突带进主程序；
- **人设**层面它只是另一个 `voice.backend`，可以和 `indextts`、`edge` 按人设混用
  （例如：日常用 edge、专属音色用 `gpt_sovits`）。
