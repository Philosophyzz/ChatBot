# 切换底座模型（9B / 14B / 27B / 35B）

目标：**不改配置文件、不重启服务**，在网页或桌宠上点一下就把对话模型换成另一个档位。
35B 要压进 10GB 显存这件事本来需要手工算账，这里把它算清楚了（第三节）。

---

## 一、三个入口，同一个 API

| 入口 | 怎么用 | 反馈 |
|---|---|---|
| **网页界面** | 左侧「系统」标签 → 底座模型 → 选档位 → 「切换模型」 | 按钮变「切换中…」，完成后弹出结果 |
| **桌宠** | 右键 → 「底座模型」 → 点档位 | 气泡显示「正在切换…需要 30~120 秒」 |
| **接口** | `POST /api/models/switch {"tier": "balanced-14b"}` | 返回新 PID、停掉的旧 PID、显存状态 |
| **开机默认** | `scripts\start-models.ps1 -Tier <id>`（改 `config\models.json` 的 `default_tier`） | 脚本日志 |

切换**只重启 8080 上的对话模型**：嵌入（8081）和重排（8082）继续跑，所以长期记忆不会
在切换过程中降级成哈希嵌入。当前状态随时可以查：

```powershell
# 档位、体积、是否已下载、当前在跑哪个、显存空闲
python -c "import json,urllib.request as u;print(json.dumps(json.load(u.urlopen('http://127.0.0.1:8077/api/models')),ensure_ascii=False,indent=2))"
```

## 二、四个档位（体积是实测值）

| 档位 | 模型 | 权重 | 显存占用 | 速度 | 现状 |
|---|---|---|---|---|---|
| `fast-9b` | Qwen3.5-9B Q4_K_M（稠密） | 5.29GB | 全部进显存 ≈ 8.5GB | 60~90 tok/s | ✅ 已下载，当前默认 |
| `balanced-14b` | Qwen3.6-14B-A3B Q4_K_M（MoE，激活约 3B） | **7.88GB** | 全部进显存 ≈ 10.5GB | 40~70 tok/s | ⬜ 待下载 |
| `quality-27b` | Qwen3.6-27B Q4_K_M（稠密） | 15.66GB | 44/64 层上 GPU ≈ 11.4GB | 9~10 tok/s | ✅ 已下载 |
| `quality-35b` | Qwen3.6-35B-A3B UD-IQ2_XXS（MoE 256 专家） | 10.02GB | **专家分流后 ≈ 9.85GB** | 5~15 tok/s | ⬜ 待下载 |

> 显存占用 = 权重 + KV cache（q8_0）+ 运行时缓冲（约 1.2GB）。
> 16GB 卡上还要给桌面/浏览器留 3~4GB —— **开着一堆网页时，能用的其实只有 10~12GB**。

## 三、35B 怎么塞进 10GB（本次的核心）

### 1. 先算清楚它是什么

`tools\plan_moe_offload.py` 只读 GGUF 文件头（几十 MB）就能算出精确账目，不用等下完 10GB：

```
python tools\plan_moe_offload.py --repo unsloth/Qwen3.6-35B-A3B-GGUF ^
    --file Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf --ctx 8192 --budget 10
```

实测输出：

```
架构 qwen35moe｜层数 40｜专家数 256
文件体积 10.02 GB｜张量合计 10.01 GB
  专家权重      8.44 GB（120 个张量）
  其余权重      1.57 GB（注意力/词表/norm 等 613 个）
KV cache（ctx=8192，q8_0）≈ 0.31 GB
```

### 2. 全部进显存是放不下的

10.01 + 0.31 + 1.2 ≈ **11.5GB** > 10GB 预算（而且 16GB 卡上桌面还要吃 3~4GB）。

### 3. MoE 给了第二条路：把专家放内存

35B-A3B 每 token 只激活约 3B 参数，其中大头是"被选中的少数专家"。llama.cpp 有
`--n-cpu-moe N`：**前 N 层的专家权重留在内存，注意力等照旧在显存**。工具会直接给出对照表：

| `--n-cpu-moe` | 显存占用 | 内存占用 |
|---|---|---|
| 0（全放显存） | 11.52GB ❌ | 0 |
| 7 | 10.06GB ❌ | 1.46GB |
| **8** | **9.85GB ✅** | **1.67GB** |
| 12 | 9.01GB ✅ | 2.51GB |

**结论：`UD-IQ2_XXS`（10.02GB）+ `--n-cpu-moe 8` → 显存约 9.85GB、内存约 1.7GB。**
这个组合已经写进 `config/models.json` 的 `quality-35b` 档位（`server_args`），点一下就生效。

想要更好的质量：换 `Qwen3.6-35B-A3B-UD-Q2_K_XL.gguf`（11.45GB），工具算出的是
`--n-cpu-moe 12` → 显存 9.98GB、内存 2.97GB。

### 4. 三条实话

1. **慢**：专家在内存里意味着每 token 要读几百 MB，速度掉到 5~15 tok/s（27B 是 9~10，
   9B 是 60~90）。它适合"我想让它聪明一点，可以等"，不适合日常闲聊。
2. **内存也要够**：专家权重放在内存里，机器最好有 16GB 以上空闲。本机 31GB 总内存，
   开着浏览器/游戏时只剩 3GB —— 那时它只能反复从磁盘读，会明显更慢。
3. **IQ2 是低比特量化**：35B 在 10GB 里的代价就是量化损失。若显存宽裕，宁可用
   `balanced-14b`（7.88GB，全进显存，质量/速度都更平衡）。

## 四、把两个新档位下下来（这一步你自己执行）

```powershell
# 14B（7.88GB）—— 16GB 卡上最舒服的一档
powershell -ExecutionPolicy Bypass -File scripts\download-models.ps1 -Tier balanced-14b -Mirror

# 35B（10.02GB）—— 需要 --n-cpu-moe 才能在 10GB 显存里跑
powershell -ExecutionPolicy Bypass -File scripts\download-models.ps1 -Tier quality-35b -Mirror
```

* `-Mirror` 走 hf-mirror.com；支持断点续传，中断了重跑同一条命令即可。
* 下完可以校验：`python tests\verify_downloads.py`
* 仓库与文件名都已用 HF API 实测解析通过（14B 8,465,553,920 字节 / 35B 10,756,586,464 字节）。
* **下完不用改任何配置文件**：网页/托盘里那个档位会从「未下载」变成可点。

## 五、切换时到底发生了什么（排错用）

1. 找出占用 `8080` 的进程（psutil → 记录过的 PID → 命令行匹配，三层兜底）并结束它；
2. 按 `config/models.json` 的 `default_server_args` + 档位自己的 `server_args` 启动新的
   `llama-server`（`--alias` = 档位 id，与启动脚本一致）；
3. 轮询 `/health` 直到就绪（最多 420 秒，加载 10GB 模型通常 30~120 秒）；
4. 把引擎里的 `llm.model` 换成新别名 —— 少这一步，健康检查会报
   「服务已启动但未加载模型 xxx」，界面变红但对话其实还能用。

| 现象 | 原因 / 处理 |
|---|---|
| 返回 409「模型还没下载」 | 按提示里的下载命令下载 |
| 启动后立刻退出，日志里有 OOM | 显存不够：关浏览器/游戏，或给档位调小 `n_gpu_layers` |
| 一直「等待模型加载」很久 | 35B/27B 权重部分在内存/磁盘，首次加载慢；超过 420 秒会报超时并附日志尾巴 |
| 找不到占用 8080 的进程 | 直接 `scripts\stop.ps1` 再切 |
| 切换后界面显示「模型错误」 | 说明第 4 步没生效：重启一次服务（`scripts\start-all.ps1`）即可 |

> 共用参数写在 `config/models.json` 的 `default_server_args` 里，
> `scripts\start-models.ps1` 与引擎的 `src\llm\supervisor.py` 读的是同一份 ——
> 这样脚本启动和界面切换不会各自演化出两套参数。

## 六、相关文件

| 文件 | 作用 |
|---|---|
| `config/models.json` | 档位定义（仓库、文件名、体积、上下文、`server_args`、取舍说明） |
| `src/llm/supervisor.py` | 停旧起新、等健康、记录 PID；`GET/POST /api/models*` 背后的实现 |
| `tools/plan_moe_offload.py` | 读 GGUF 头算显存/内存账，给 `--n-cpu-moe` 推荐值 |
| `scripts/download-models.ps1` / `start-models.ps1` | 下载 / 开机默认档位 |
| `tests/test_model_switch.py` | 档位列表、未下载报错、别名重绑定等回归测试 |
