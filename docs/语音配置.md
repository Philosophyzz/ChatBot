# 语音配置：让它说话好听

需求是"语音输出要甜美，支持设置各种人设"。这份文档说明怎么做到，以及每档音质的代价。

---

## 一、三条路线，按需选

| 路线 | 音质 | 音色克隆 | 显存 | 联网 | 上手难度 |
|---|---|---|---|---|---|
| **edge-tts**（默认兜底） | 好，微软神经音色 | ✗ | 0 | 需要 | 装好即用 |
| **IndexTTS2**（本地） | 很好，可克隆任意音色 | ✓ | ~2GB | 不需要 | 需要单独环境 |
| **Windows SAPI** | 一般，机械感 | ✗ | 0 | 不需要 | 系统自带 |

系统默认策略是 **本地优先、在线兜底**：`speech.tts_preference: [indextts, edge, sapi]`，
路由器会探测健康状态，本地不可用时自动切在线，**任何情况下都不会"没声音"**。

## 二、快速获得"甜美音色"（5 分钟，零显存）

开箱即用。推荐的中文女声音色（`voice.voice_id`）：

| voice_id | 特点 | 适合人设 |
|---|---|---|
| `zh-CN-XiaoxiaoNeural` | 温柔甜美，最常用的"女友音" | 小甜 / 温柔姐姐 |
| `zh-CN-XiaoyiNeural` | 活泼俏皮，少女感 | 活泼型陪伴 |
| `zh-CN-liaoning-XiaobeiNeural` | 东北口音，接地气 | 幽默损友 |
| `zh-CN-YunxiNeural` | 男声，清朗 | 助理 / 技术顾问 |
| `zh-CN-YunyangNeural` | 男声，播音腔 | 讲解 / 老师 |
| `zh-HK-HiuMaanNeural` | 粤语女声 | 粤语人设 |

完整列表：

```powershell
# 起服务后
curl http://127.0.0.1:8077/api/voice/tts/voices
```

### "甜美"是怎么调出来的

edge-tts 本身没有情感参数，所以系统把 `emotion` 映射成**语速 + 音高**的韵律调整
（映射表在 `src/speech/tts.py::_EDGE_EMOTION_STYLE`）：

```yaml
voice:
  voice_id: zh-CN-XiaoxiaoNeural
  speed: 1.03              # 略快一点更活泼
  emotion: sweet           # → 语速 +4%，音高 +2.5 半音
  emotion_alpha: 0.9       # 情感强度，0~1
  pitch_shift: 1.5         # 再手动加一点亮度和甜度
```

想让声音更"甜"，按效果排序调这三个：**`pitch_shift`（+1 ~ +3 最明显）→ `emotion_alpha`
→ `speed`（1.0~1.08 之间）**。过了会失真，建议小幅试。

在网页界面「人设 → 编辑」里改完直接保存，下一次朗读就生效。

## 三、本地克隆音色（IndexTTS2）

想要**完全离线**、并且能**克隆特定音色**（比如你自己的声音，或某段喜欢的配音），
就用 IndexTTS2。它支持零样本克隆：给 5~15 秒参考音频，不需要训练。

### 3.1 装在哪：统一进 conda 环境 `chatbot`

推荐把 `indextts` 直接装进主环境（`conda activate chatbot`）：依赖只装一份，
而且 `src\speech\tts.py` 检测不到独立环境时会自动改用**进程内导入**，不需要改任何配置。

> 想隔离也可以（`scripts\install-tts.ps1 -EnvName chatbot-tts`）：那样主程序会通过
> `tools\tts_worker.py` 这个常驻 JSON 子进程桥调用（stdin/stdout 一行一个 JSON，
> 模型加载与推理输出转到 stderr，写进 `logs\tts-worker.log`）。
> 需要隔离的唯一理由是下面这个版本冲突。

**必须知道的冲突**：`indextts` 钉死 `numpy==2.2.6`，而 GPT-SoVITS 的
`requirements.txt` 写 `numpy<2.0`，pip 在同一环境里无法同时满足这两条。
实践顺序是「先装 GPT-SoVITS 的依赖，再把 numpy 抬回 2.2.6」，然后验证：

```powershell
python tools\check_tts_stack.py     # 两个 TTS 栈都能导入才算成功
```

若验证报「导入失败 + numpy」，说明某个扩展模块绑定了 numpy 1.x 的 ABI，
这时 GPT-SoVITS 训练只能改用独立环境：
`scripts\install-gptsovits.ps1 -EnvName chatbot-tts-train`

### 3.2 安装步骤

```powershell
conda activate chatbot

# 1) torch（CUDA 版；IndexTTS2 要求 torch==2.8.*）
python -m pip install torch==2.8.* torchaudio==2.8.* --index-url https://download.pytorch.org/whl/cu128

# 2) index-tts 包本身（会带上它钉住的 numpy==2.2.6 / transformers 等）
python -m pip install -e D:\Harness\ChatBot\vendor\index-tts -i https://pypi.tuna.tsinghua.edu.cn/simple

# 3) 验证：能导入 + 看得到 CUDA
python -c "from indextts.infer_v2 import IndexTTS2; import torch; print('ok, cuda', torch.cuda.is_available())"
```

权重已经下好（`models\tts\IndexTTS2`，5.9GB），不需要再下载：

```powershell
Get-ChildItem D:\Harness\ChatBot\models\tts\IndexTTS2 -Recurse -File | Measure-Object Length -Sum
```

如果以后要重下或换机：`python tools\download_file.py --url <直链> --out <文件> --chunk-mb 24`
（分块+断点续传+sha256 校验；比 `hf download` 更适合大文件，详见 README 的下载章节）。

### 3.3 准备参考音频（决定音色）

这是**最影响成品效果的一步**，比选模型更重要：

| 要求 | 说明 |
|---|---|
| 时长 | 5~15 秒（太短音色不稳，太长没收益） |
| 内容 | 自然说话的连续句子，避免念稿腔 |
| 环境 | 无背景音乐、无混响、无他人说话 |
| 格式 | WAV / MP3 均可，采样率 ≥16kHz |
| 情绪 | **录成你想要的情绪**——想要甜美就录甜美的语气 |

放在 `models\voices\` 下，例如 `models\voices\sweet_girl.wav`。
安装脚本会在缺失时用 `tools\make_reference.py` 生成一个占位文件
（默认 `models\voices\default_sweet.wav`）——**建议换成你自己的录音**，同一个路径覆盖即可。

> 想要"甜美"的关键：参考音频本身就是甜美的。模型克隆的是**音色 + 说话方式**，
> 用平淡的参考音频很难合成出甜美的效果。

> 版权提醒：克隆他人享权利的商业音色（包括在线 TTS 的输出）请仅限个人自用，
> 不要传播或用于公开内容。

### 3.4 显存与速度（16GB 卡上的实测口径）

IndexTTS2 用 fp16 常驻约 2~4GB，和 9B 对话模型（约 8.7GB）同时在场会接近 12.5GB 上限，
所以：

* 模型**懒加载**：第一次说话才加载（20~40 秒），之后每块约 1~3 秒；
* **空闲自动卸载**：`config.yaml` 的 `tts.indextts.idle_unload_s`（默认 600 秒）
  到点把显存还给大模型，日志里会看到 "IndexTTS2 unloaded"；
* 显存实在紧张时，把 `speech.tts_preference` 改成 `[edge, indextts, sapi]`，
  平时用在线音色，需要克隆音色的人设再在 `voice.backend: indextts` 里单独钉住。

速度旋钮（都与后端无关，在线/本地都吃这套）：

| 配置 | 默认 | 说明 |
|---|---|---|
| `speech.tts_chunk_chars` | 40 | 每块字数 ≈ 你等第一个字的时间（40 字约 2~4 秒语音） |
| `speech.tts_chunk_concurrency` | 2 | 并发合成几块；本地后端可以调到 3~4 |

### 3.4 在人设里启用

```yaml
# config/personas.yaml
cloned_sweet:
  voice:
    backend: indextts
    reference_audio: models/voices/sweet_girl.wav
    reference_text: "这是参考音频里说的那句话"   # 填上能提升稳定性
    emotion: sweet        # 情感由这个字段控制，与音色解耦
    emotion_alpha: 0.9
    speed: 1.02
```

也可以不改文件，在网页「人设 → 编辑」里把"语音后端"选成 `indextts`，
"参考音频"填相对路径即可。

**音色与情感是解耦的**：同一段参考音频，把 `emotion` 从 `sweet` 改成 `calm`，
就会用同样的音色说平静的话。这是 IndexTTS2 相对普通 TTS 的核心价值。

| 人设 | 音色 | 情感 | 语速 | 效果 |

## 五、语音输入（识别）

| 参数 | 默认 | 调优建议 |
|---|---|---|
| `stt_model` | `large-v3-turbo` | 中文识别用它性价比最高；显存紧张改 `small` |
| `stt_device` | `cuda` | 27B 档位建议改 `cpu`，把显存全留给大模型 |
| `stt_compute_type` | `int8_float16` | CPU 上用 `int8` |
| `stt_language` | `zh` | 固定语言能避免误判，也更快 |
| `stt_idle_unload_s` | `900` | 想更快释放显存改成 `300` |
| `vad_filter` | `true` | 自动裁掉静音，省时间，建议保持 |

### 录音链路

前端用 Web Audio 直接编码成 **16kHz 单声道 WAV** 再上传，所以：

* **不需要 ffmpeg** 就能用语音输入（这是默认路径）
* 服务端只在收到 WebM/OGG 等格式时才需要 ffmpeg 转码

想装 ffmpeg 以支持任意格式：`winget install Gyan.FFmpeg`

按住 **空格** 或 **🎤 按钮** 说话，松开即识别。太短（<0.1s）或没有有效人声会被明确拒绝
并给出提示，而不是把静音丢给模型。

## 六、流式朗读：为什么感觉"反应快"

回答不是等全部生成完才合成，而是**按句子流式合成**：

```
模型生成第 1 句 ──→ 立刻合成第 1 句 ──→ 开始播放
模型生成第 2 句 ──→ 合成第 2 句 ──→ 排队播放（无缝衔接）
```

代码在 `core/chat.py::synthesize_speech()`（用 `core/utils.py::split_sentences` 切句）。
效果是首字延迟从"整段合成时间"降到"一句话的合成时间"。

Markdown 会被自动剥离（`speakable_text()`），所以不会被念出"星号星号"和代码块——
同时人设的提示词里也约束了"不要输出 Markdown"，双保险。

## 七、常见问题

**先跑这个再排查**（它会一次性告诉你到底是哪个后端、哪个参数出的问题）：

```powershell
python tests\diagnose_voice.py
```

服务已在运行时，也可以直接问接口（含每个后端的完整 traceback）：

```powershell
curl "http://127.0.0.1:8077/api/voice/tts/diagnose"
```

| 现象 | 原因与处理 |
|---|---|
| 完全没声音 | 跑上面的诊断；在线音色需要联网 |
| **声音很机械、像上世纪的机器人** | 说明回退到了 Windows SAPI。原因通常是 edge 不可用（无网络/被限流）。诊断接口会显示每个后端的状态与错误；SAPI 已被固定为最后兜底，正常情况下不该被选中 |
| 提示"未安装 edge-tts" | `conda activate chatbot` 之后 `pip install edge-tts` |
| 合成返回 200 但很短（几十字节） | 空音频。代码已把"仅 WAV 头"判为失败并自动换后端；若仍出现，诊断接口会指出是哪个后端 |
| **用 PowerShell 测接口总是只有几十字节** | 这是 **Windows PowerShell 5.1 的 `Invoke-WebRequest` bug**：它读不了 chunked 传输的响应体，只拿到第一段就报数。用 `curl.exe`、Polaris（`pwsh`）或浏览器验证；前端用 `fetch().blob()` 不受影响 |
| 声音偶尔变成机械音（SAPI） | edge 服务端临时拒绝（`NoAudioReceived`）。代码已做 3 次重试并记录日志；偶发属正常，持续出现说明网络受限，可考虑装 IndexTTS2 或改用 `openai` 后端 |
| 提示需要 ffmpeg | `winget install Gyan.FFmpeg`；或改用浏览器内置录音（默认已用） |
| 克隆音色不像 | 参考音频质量是决定性的：换一段干净、情绪匹配的 5~15 秒音频 |
| 克隆报"缺少参考音频" | 人设里的 `reference_audio` 路径写错，或文件不在 `models\voices\` |
| 声音太尖/太慢 | 调 `pitch_shift`（±3 以内）与 `speed`（0.9~1.15） |
| 语音加载后生成变慢 | 显存被抢：把 `stt_device` 改 `cpu`，或调小 `stt_idle_unload_s` |
| 朗读数字/英文很怪 | 人设提示词里加一句"数字和单位用中文口语表达" |

### 后端选择顺序是怎么定的

`config.yaml` 的 `tts.tts_backends.<name>.priority` 是**权威顺序**（数字越小越优先）：

| 后端 | 默认 priority | 说明 |
|---|---|---|
| indextts | 10 | 本地克隆音色，音质最好 |
| edge | 20 | 在线神经音色，中文很自然 |
| openai | 30 | 自建/第三方 TTS 服务 |
| sapi | 90 | Windows 自带，永远可用但音色机械 |

`speech.prefer_offline` 只作为**同优先级时的次要键**（隐私优先：不让文本离开本机）。
它**不会**把 SAPI 提到前面 —— 这一点曾经写错，导致为了"离线"而牺牲音质，
现在由 `tests/test_engine_api.py::test_tts_router_orders_by_quality_not_offline` 锁住。
