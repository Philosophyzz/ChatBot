## 一、它是什么

一台 16GB 显存的 Windows 机器上，**全部推理本地完成**的中文语音聊天机器人：

* 大模型在本地（llama.cpp + Qwen3.5-9B Q4_K_M，全部层在 GPU）
* 语音识别在本地（faster-whisper large-v3-turbo，int8，实测 12 秒音频 0.35 秒）
* 语音合成在本地（IndexTTS2 零样本克隆；不可用时自动切在线 edge 音色）
* 长期记忆在本地 SQLite（分层：情景 / 语义 / 图谱 / 档案 / 反思）
* 三种使用形态：**网页界面**、**桌宠 exe**、**HTTP/WebSocket 接口**

```
┌─ 使用形态 ─────────────────────────────────────────────────────────┐
│  web/ 网页界面          桌宠 dist\ChatBotPet.exe     其它程序/脚本   │
│  (原生 JS，无构建)       (PySide6，置顶可拖动)        (OpenAI 兼容) │
└──────────┬───────────────────────┬───────────────────────┬─────────┘
           │ HTTP / WebSocket      │ HTTP (瘦客户端)        │
           ▼                       ▼                       ▼
┌─ 应用服务（1 个进程，默认 127.0.0.1:8077）──────────────────────────┐
│  api/        FastAPI：35 个路由 + 1 个 WebSocket                    │
│  core/       配置 / 注册表 / 会话 / 编排引擎 / 工具                  │
│  persona/    12 个人设（提示词 + 音色 + 采样 + 记忆作用域）          │
│  memory/     抽取 → 消解 → 去重 → 冲突消解 → 落库；三路混合检索      │
│  speech/     STT / TTS 路由与全部后端                               │
│  llm/        对话/嵌入/重排客户端 + 底座模型切换（supervisor）       │
│  pet/        桌宠窗口、形象、免提监听、麦克风、扬声器、后端客户端     │
│  plugs/      可选插件（放进去自动加载）                              │
└──────────┬───────────────────────────────────────────┬─────────────┘
           │ OpenAI 兼容 HTTP                          │ SQLite
           ▼                                           ▼
┌─ 模型服务（独立进程）──────────────┐      ┌─ 数据（全部在 D 盘）───────┐
│ llama-server  :8080  对话 9B      │      │ data/memory.sqlite3       │

│ （可选）      :8082  重排 0.6B    │      │ logs/    运行日志         │
│ （可选）      :9090  GPT-SoVITS   │      │ config/  4 个配置文件     │

```

## 三、四条主数据流

**1. 文字对话**（网页或接口）

```
用户输入 → core/chat.py 组装上下文
   ├─ 会话历史（按 token 预算裁剪，中间丢弃）
   ├─ 系统提示词（人设系统提示 + 记忆使用约定 + 时间 + 长期记忆块）
   └─ 长期记忆检索（memory/retrieve.py：向量 + BM25 + 图谱 + 档案直注，融合+重排+时间衰减）
→ llm/openai_compat.py 流式调用 llama-server（SSE 分块）
→ 逐块回前端（WebSocket/SSE）并落库 messages
→ 一轮结束后异步写入记忆（memory/extract.py，不阻塞回复）
```

**2. 语音输入**（桌宠按住麦克风 / 网页 🎤）

```
Python 端录音（桌宠，16kHz 单声道）或浏览器 Web Audio 编码 WAV
→ POST /api/voice/stt → speech/stt.py faster-whisper（cuda，int8）
→ 文本 → 走上面的文字对话
```
> 桌宠在 **Python 侧**录音而不是浏览器侧，是为了绕开 WebView2 的麦克风权限回调。

**3. 语音输出**（朗读回复）

```
回复文本 → core/utils.split_sentences（按 speech.tts_chunk_chars 切块，默认 40 字）
→ speech/tts.py TTSRouter 选后端（indextts → edge → sapi，按健康探测与失败冷却）
→ 逐块返回：【分帧】4字节长度 + 1字节tag + 负载（tag=A 音频，tag=M 元数据）
→ 桌宠 sounddevice 播放 / 网页边收边播（第一块到达即出声）
```

**4. 桌面宠物**

```
run_pet.py（或打包好的 exe）
├─ 单实例守卫：同一个人设只允许开一只（命名互斥体 Local\ChatBotPet_<人设>）
│    已开着 → 把那只切到前台后自己退出，不再叠一只出来
├─ 无边框置顶窗口：默认用 QPainter 画角色；内置 3 个二次元形象（樱樱/薄荷/露娜，
│    见 src\pet\assets）+ 呼吸/摆动/歪头/点击跳跃等程序动画，也可导入自己的图片
│    不同人设可以同时开：新桌宠会自动往左找空位，不再两只叠在同一像素
├─ 按住麦克风按钮 → pet/audio.py 录音 → pet/client.py → /api/voice/stt
├─ 「一直听着」= 免提：点一次就连续对话，靠自适应噪声门自动断句（pet/hands_free.py）
├─ → /api/chat（SSE）→ 气泡逐字显示 → /api/voice/tts/stream → 分段播放
│    气泡每次显示/变高都会重新定位到桌宠上方（否则无边框窗口会出现在屏幕中间）
└─ 托盘菜单：打字聊天 / 一直听着 / 免提灵敏度 / 静音朗读 / 更换形象 / 底座模型 /
              切换人设 / 启动本地服务 / 退出
```

## 六、配置与存储

**配置（4 个文件，优先级从低到高）**

| 文件 | 内容 |
|---|---|
| `config/config.yaml` | 主配置：llm / memory / extraction / speech / server / embedding / reranker / tts |
| `config/models.json` | 模型档位表：`Qwen3.5-9B-Q4_K_M`（默认，5.29GB，全 GPU，32K 上下文）、`Qwen3.6-27B-Q4_K_M-mtp`（15.66GB，44 层在 GPU） |
| `config/personas.yaml` | 7 个人设（温柔姐姐/阿澈/深夜电台/私塾先生/技术顾问/灵感搭档/专属音色），热加载 |
| `config/local.yaml` | 运行时覆盖（设置界面写入），优先级最高；`CHATBOT_*` 环境变量再高一层 |

**长期记忆库 `data/memory.sqlite3`（12 张表）**

| 表 | 作用 | 现在 |
|---|---|---|
| `conversations` / `messages` | 会话与消息，`messages_fts` 做全文索引 | 3 / 6 |
| `memory_items` (+`memory_fts`、`memory_vectors`) | 事实/偏好/档案/关系/情景/摘要/反思七类条目 + 向量 | 6 |
| `entities` / `entity_aliases` / `entity_vectors` | 实体与别名消解（"我/用户/小明"归一） | 9 / 12 |
| `relations` | 带有效期窗口的关系边（新事实关闭旧边=取代链） | 3 |
| `profiles` | 档案槽位（姓名、职业、喜好…），键名会归一 | 0 |
| `turn_log` | 每轮抽取的去重与状态（幂等保证） | 20 |
| `kv_store` / `schema_meta` | 杂项与 schema 版本 | 1 / 1 |

## 七、接口面（35 个路由）

* 诊断：`GET /health`、`GET /config`、`PATCH /config`、`GET /plugins`、`POST /shutdown`（仅本机）
* 底座模型：`GET /models`（档位/是否下载/当前/显存）、`POST /models/switch`（停旧起新，30~120 秒）
* 人设：`GET /personas`、`GET/DELETE /personas/{id}`
* 会话：`GET/POST /sessions`、`GET/PATCH/DELETE /sessions/{id}`
* 对话：`POST /chat`（非流式/SSE）、`WS /ws/chat`
* 语音：`POST /voice/stt`、`POST /voice/tts`、`POST /voice/tts/stream`（分帧）、`GET /voice/tts/diagnose`、`GET /voice/tts/voices`
* 记忆：`GET /memory/stats|items|search|history|graph|profile`、`POST/PATCH/DELETE /memory/items`、`DELETE /memory/profile`、`POST /memory/consolidate`、`POST /memory/extract/{session_id}`

## 八、运行环境（conda `chatbot`，全部在 D 盘）

| 组件 | 位置 | 说明 |
|---|---|---|
| 应用环境 | `D:\conda-envs\chatbot` | Python 3.11.16，**所有依赖都在这里**（含 torch 2.8+cu128） |
| 包缓存 | `D:\conda-cache\pip`、`D:\conda-pkgs` | pip / conda 缓存都在 D 盘 |
| 对话模型 | `models\gguf\Qwen3.5-9B-Q4_K_M.gguf` | 5.29GB，全层 GPU，~125 tok/s |
| 备用大模型 | `models\gguf\qwen3.6-27b-q4_k_m.gguf` | 15.66GB，需部分层落内存，~10 tok/s |
| 语音识别 | `models\whisper\large-v3-turbo` | 1.6GB，哈希校验过；CUDA 运行库自动复用其他环境的 torch\lib |
| 语音合成 | `models\tts\IndexTTS2`（5.9GB + `hf_cache` 5.11GB 辅助模型） | 零样本克隆，7 个参考音色在 `models\voices` |
| 可训练 TTS | `vendor\GPT-SoVITS`（源码 + 5.3GB 预训练 + G2PW + ffmpeg） | 微调用，权重与代码齐全 |
| TTS 源码 | `vendor\index-tts` | `pip install -e` 装进 chatbot 环境 |
| 推理引擎 | `bin\llama.cpp\llama-server.exe` | CUDA 13.4 build 11067 |

**显存现实**（16GB 卡）：9B 全层约 8.7GB + 桌面/浏览器 3~4GB + 你的其它任务。
空闲充足时 IndexTTS2 实测 RTF 2.36（3.95 秒音频 9.3 秒合成，占约 871MB）；
显存被占满时 RTF 8.76（4.61 秒音频 40 秒）。当前配置是 `tts_preference: [indextts, edge, sapi]`，
即**默认用 IndexTTS2**，接受在显存紧张时较慢；想换成快的把 `edge` 提到第一位即可。

## 十一、已知约束（诚实清单）

1. **显存是硬约束**：9B 全层 + 桌面已占约 12GB。IndexTTS2 在显存紧张时 RTF ~9（每句 20~40 秒）；
   27B 档位必须部分层落内存（~10 tok/s）。
2. **嵌入/重排服务没启动**（8081/8082）：记忆检索降级为哈希嵌入 + 词法，语义召回变弱但不报错。
3. **训练流程未端到端跑过**：数据准备工具实测过（合成音频切 4 段、list 格式正确），
   但真正的 GPT-SoVITS 微调需要你的语音素材，脚本已就绪、`-DryRun` 可先看计划。
4. **桌宠的「一直听着」是能量门限 VAD + 自适应噪声底**：安静房间很准，但**外放 / 键盘声大**
   时容易把环境噪声当说话（切「抗噪」档）；反过来**档位偏高时小声说话会完全触发不了**，
   表现就是"语音识别失败"。拿不准就跑 `python tools\check_hands_free.py --calibrate`
   —— 它先静 2 秒测噪声、再让你说一句话测音量，然后推荐该用哪一档；免提开着 20 秒完全
   没听到接近阈值的音量时，桌宠自己也会提示一次。宠物说话期间监听会暂停（否则它会录到
   自己的声音并自问自答）。
5. **三个 GPU 模型不能同时驻留**（对话 9B 5.3GB + whisper 1.8GB + IndexTTS2 4GB > 16GB，
   桌面还要占 3~4GB）。超了的后果**不是异常，而是进程被原生代码 fail-fast 干掉**：
   2026-09-22 21:16:48 的 Windows 事件日志记着 `python.exe` / `ucrtbase.dll` / `0xc0000409`，
   接下来网页就是 "Failed to fetch"、桌宠就是"连不上本地服务"。现在 `core/vram.py` 的守卫
   会在加载其中一个之前先把另一个卸掉（`speech.vram_guard` 可关），
   状态见 `GET /api/health` 的 `vram_guard`。
6. `pyopenjtalk`（日文前端）因 `setuptools 83` 移除 `pkg_resources` 导入失败；
   中文路径不经过它（`cleaner.py` 按语言惰性 import），要修就 `pip install "setuptools<81"`。
6. **14B / 35B 档位的模型需要你自己下载**（`Qwen3.6-14B-A3B-FableVibes-Q4_K_M` 7.88GB、`Qwen3.6-35B-A3B-UD-IQ2_XXS` 10.02GB）：
   接口与界面会把未下载的档位标出来并给出下载命令。35B 用的是 IQ2_XXS + `--n-cpu-moe 8`
   （显存 ≈9.85GB、内存 ≈1.7GB），速度只有 5~15 tok/s —— 细节与换算表见
   [模型切换.md](模型切换.md)。
7. **打包桌宠 exe 的已知坑**（都踩过、都已修，重新打包时注意别退回去）：
   * *体积*：`src\plugs\__init__.py` 会 import `speech.stt`/`speech.tts` 来注册内置插件，
     PyInstaller 顺着这条静态边把 torch 整套 CUDA 库也打了进来 —— 出过 3.3GB 的 exe
     （光 `torch_cuda.dll` 就 981MB）。现在 `build-pet.ps1` 排除 35 个重量级包、卡 400MB
     上限，正常体积 ~80MB。
   * *缺 DLL*：conda 把 C 运行库放在 `<env>\Library\bin`，PyInstaller 不会自动带。
     少了 `libexpat.dll` → 启动钩子 `pyi_rth_pkgres` 加载 `pkg_resources` 时炸掉，
     `--windowed` 下表现为弹一个 "Unhandled exception in script" 然后**一直等人点确定**
     （构建脚本曾经因此卡死）；少了 `ffi-8.dll`（conda 不叫 `libffi-8.dll`，PyInstaller
     按后者找，自然找不到）→ 一切到 `ctypes` 就 `import _ctypes: DLL load failed`，
     用户看到的是"桌宠启动失败"对话框 —— 而**自检当时没走到 ctypes**，所以漏了出去。
     现在 ssl/crypto/ffi/expat/sqlite3/lzma/bz2/zlib 全部一起打包，并且 `--import-check`
     会把 57 个运行时模块挨个导入一遍（含 ctypes + EnumWindows 实调），漏 DLL 当场失败。
   * *弹窗会挂住自动化*：`--report` 模式下桌宠不再弹模态对话框（脚本看的是文件），
     构建脚本的冒烟测试也都带超时。
8. **单实例守卫是"每会话"的**：命名互斥体用 `Local\` 命名空间，同一台机器不同登录会话
   各有一只桌宠是允许的（正常桌面场景只有一个交互会话）。
9. **两套坐标单位（高分屏陷阱）**：这台机器是 3840×2160 @175%，Qt 用的是逻辑像素
   （桌宠在 `1943,915`），而 Win32 的 `GetWindowRect` 在感知 DPI 的进程里返回物理像素
   （同一只桌宠是 `3400,1601`）。桌宠找空位时要先把 Win32 坐标除以 `devicePixelRatio`
   （`window._to_logical`），否则在 100% 缩放下正常、在缩放屏上就会把两只桌宠叠在一起。
   `tools\inspect_windows.py` 是不感知 DPI 的普通进程，它打印的坐标天然是逻辑像素。
